# The sixty-four: what is written

Generated by `npm run progress`, last run 2026-09-24. Never edit by hand: it is
read off the cards themselves, so it cannot drift.

## How to use this, Adrian

**To see where things stand:** `npm run progress`, then open this file. The counts at
the top are read off the cards, so they are never a guess.

**To have a card written:** tell a session "write card NN" and it takes the first
unticked card from "not started" on its own. One writer, one card: the worksheet first, then the sections, then the
entrance, then the gate. Nothing to brief: the rule is in the repo.

**To finish a card:** read it on the page, and when it holds, say so. That sets every
section's status to `final` and the card moves to "finished". Nothing else marks a card
done, and no script or writer may. If a card is close but not right, say what is wrong
and it goes back to the writer with your words.

**The one thing to avoid:** do not ask two sessions to write the same card. Each one
takes the next unticked card by itself, so the way to avoid it is simply not to name
numbers. If you want to steer, name a range, not a card.

**Where everything lives now:** all of it is on `main`. The card-writing branch and the
entrance-template branch are both closed, so there is nothing else to open and nothing
in flight anywhere else.

Three states, and a card is only 100% when all three hold.

1. **Sections written**: the sentence check finds nothing to gate, which a card only
   reaches by going through the pass.
2. **Through the gate**: `npm run card:gate -- NN` passes. That means the six steps in
   [the card pass](CARD-PASS.md) were followed: the card placed among its neighbours, six different
   facets, the sideways read, and a fresh reader who named this card and found no repeats.
3. **Adrian's yes**: every section's status says `final`. That is his editorial decision
   and never an automated score, so no script sets it and no writer may set it.
